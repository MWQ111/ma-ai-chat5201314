# Agent Loop 架构

> ma-ai-chat 的 Agent 主循环设计：规划、执行、终止、成本与工具接入。

## 主循环

本项目是 ReAct 风格的单 Agent 循环：

用户输入
  → LLM 规划：判断是否需要调用工具；需要则生成工具调用工单
  → 代码执行：解析工单，执行对应工具，把结果返回给 LLM
  → LLM 判断：结合工具结果判断能否回答用户问题
      → 能 → 输出结果，结束
      → 不能 → 继续规划，回到循环

三个核心节点：规划（LLM）、执行（代码）、结束（输出）。
反思体现在"不能回答 → 继续规划"这条回边上：
LLM 每轮基于最新的工具结果重新评估，直到能给出回答。

## 停止机制

两层保险：

1. 软停：LLM 自己判断"能否回答"，能回答则结束循环
2. 硬停：代码规定最大循环次数，防止 LLM 无限重试

达到上限后如果仍无法完整回答，系统如实返回已有内容，
并友好提示"尚未回答完毕"，不做静默截断。

## 成本控制

每轮的工具调用结果全部进入上下文，供下一轮参考；
循环越多，token 成本线性上涨。

项目设置两道限制：

- 上下文最大 token 量
- 循环最大次数

## 工具接入

模型知道"有哪些工具可开"的唯一来源，是随每次请求注入的
tools 字段——由开发者在代码中定义（名称、描述、参数），
随请求发出，模型据此生成工具调用工单。

> 说明：本项目为单 Agent 循环 + 本地工具，未接入 MCP。
> MCP 是工具侧的标准化协议（解决 M 个模型 × N 个工具的
> 适配问题，M×N 变 M+N），属于我了解的行业方案。
